Do you need a persistent object cache?

A page cache answers most requests without PHP at all, which is why an object cache is often the second purchase rather than the first. It pays off on sites that stay uncacheable: shops with carts, membership sites, anything with a logged-in audience — and only if a persistent backend is actually connected.

What an object cache stores

Query results and computed values, keyed by the query. Within one request it is always worth having. Across requests it needs Redis or Memcached; without a backend the cache lives in PHP memory and dies with the request, which is where most 'object caching did nothing' stories come from.

How {name} approaches it

Rowan Edge Cache reports object-cache counters and does not ship a drop-in replacement: if your host provides Redis, the counters show whether it is helping; if not, the plugin stays out of the way rather than pretending.

The invalidation trap

Every write must invalidate the keys it affects. Plugins that cache aggressively without group invalidation produce stale prices and phantom stock. Check that changing a product price shows up on the next request before trusting the setup.

Where it beats a page cache

A cart page cannot be served as shared HTML. Its cost is the queries behind it, and those are exactly what an object cache serves from memory. On a busy shop this is often the difference between 400 ms and 120 ms per uncached request.

The honest test is a stopwatch, not a score. Load the same page five times with the plugin disabled and five times with it enabled, on the same network, and compare the median. Then check the cache page for a miss count that keeps rising on pages you never visit - that is usually a query string, a cookie, or a form that should have been excluded.

Rowan Edge Cache records what it did per request: whether it served from cache, how many bytes it saved, and how long generation took. Those three values are enough to tell a working setup from one that only looks configured.

Who this is for

The useful test: do you administer the site yourself, and does it run on hosting you can restart? If yes, Rowan Edge Cache is the whole performance stack. If someone else owns the platform and the CDN, the plugin is a smaller piece of a larger puzzle and the counters here will tell you how much of the problem was yours to begin with.

What it does not do

No CDN. No image CDN. No edge computing, no page builder, no backup, no security firewall. Rowan Edge Cache does not rewrite your theme, does not inject a dashboard banner asking for a review, and does not phone home unless the administrator ticks the box on the dashboard. If a feature needs a remote service to work, it does not belong in a cache plugin.

Frequently asked

Is object caching the same as page caching?

No. Page caching stores finished HTML for anonymous visitors; object caching stores query results for any request, including logged-in ones.

Do I need Redis?

For cross-request benefit, yes — or Memcached. In-process caching alone rarely changes a number you can measure.

Can the two conflict?

They compose, but a page cache serving stale HTML can hide an object-cache invalidation bug. Test with the page cache off first.
